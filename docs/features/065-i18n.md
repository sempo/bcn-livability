# 065 — Internationalisation (EN / ES / CA, any number of languages)

Replaces TODO-028.

## Idea

Any number of languages. A menu in the brand bar (left of Share) lists them by their own names. EN is the source
text and the fallback; ES and CA are the first two translations. Translations live in separate JSON files per
language and namespace, so that a translator works without the code (see `docs/TRANSLATING.md`).

## Decisions

- i18next + react-i18next; keys in code, English is a file like the others; plurals by CLDR (`key_one`, `key_other`).
- `src/locales/<lang>/<namespace>.json`; English in the bundle, other languages fetched when chosen.
- Language order of choice: `?lang=` → localStorage `bcn_lang` → browser languages → `VITE_DEFAULT_LANG`.
  `?lang=` is written to the address only when it is not the default; the share link keeps it.
- ENV: `VITE_DEFAULT_LANG` (en), `VITE_ENABLED_LANGS` (en,es,ca).
- Not translated: barri / municipality names, brand names.
- `src/i18n/locales.test.ts` checks that every enabled language has the English keys and placeholders.

## Not in this feature (follow-ups)

- Share pages and pictures (`dist/share/...`, `og-image`) and the static `index.html` tags stay English; per-language
  versions and `/es/` path prefixes for SEO come with the static pages (TODO-030).
- A translation platform (Weblate / Crowdin) once there is a translator.

## Notes for the code

- Texts that used to be constants are read on each use (`lazyLabels`, getters on `SERVICE_CATEGORIES`, `LANDMARKS`,
  `AGE_ERAS`, `profileName()` / `profileBlurb()`), so a language switch reaches them. Never copy them with a spread
  at module load.
- Sentences with controls inside use `<Trans>` with tags (`<limit/>`), so each language orders the words itself.
- The language list falls back to `en,es,ca` when `VITE_ENABLED_LANGS` is unset (the dev server does not read `.env.production`).
- Bundle: i18next + react-i18next + the English files raised the initial JS from ~484 to ~521 KB gzip; the budget
  is 530 KB now.
